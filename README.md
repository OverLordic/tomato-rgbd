# Оценка признаков томата по RGB-D изображениям

По снимку растения сверху модель предсказывает высоту, сырую массу, площадь листьев и количество красных плодов

 Датасет WUR: 479 растений карликового томата четырёх сортов A, B, C, D. Сравниваются модели на вычисленных признаках, ResNet18 по RGB и RGB-D, а также геометрические признаки из облака точек

## Итоговая модель и результат

Выбрана ResNet18 с четырьмя входными каналами: RGB и выровненная карта глубины. Предобученные веса - ImageNet1K. Для итогового прогноза усредняются ответы пяти моделей, обученных на разных фолдах папок development

- Изображения приводятся к 320*320 с сохранением пропорций и дополнением нулями
- RGB нормализуется статистиками ImageNet
- Глубина хранится в миллиметрах и делится на 2000 при подаче в сеть
- Нулевая глубина означает отсутствие измерения
- Кадрирование не используется
- Ответы предсказываются в шкале log1p и возвращаются в исходные единицы через expm1
- При обучении обновляются последний блок ResNet, выходной слой и веса канала глубины в первой свёртке

Финальная оценка выполнена один раз на 96 отложенных растениях, которые не участвовали в подборе моделей и параметров

| Признак | RMSRE  |      MAE  |
|---|---:|---:|
| Высота | 0,1256 | 3,49 см |
| Сырая масса | 0,2389 | 32,16 г |
| Площадь листьев | 0,1911 | 166,36 см² |
| Количество красных плодов | 0,1832 | 1,26 плода |
| Среднее RMSRE | **0,1847** | - |

На 23 растениях holdout с ненулевым числом плодов MAE составляет **5,23 плода**. Общая ошибка ниже из-за большого числа растений без красных плодов

## Разбиение и метрика

- 383 растения используются для разработки и пятифолдовой кросс-валидации
- 96 растений, или 20%, отложены для единственной финальной оценки
- Holdout и фолды стратифицированы по сорту, seed=42
- Сохранённые ID находятся в `splits/`; исходные папки соревнования не определяют наше разбиение
- Сорт используется для разбиения и анализа, но не подаётся основной CNN как вход
- Пропущенные ответы исключаются отдельно для каждого признака

Для каждого признака вычисляется по формуле:

```text
RMSRE = sqrt(mean(((prediction - truth) / (truth + 1))**2))
```

Итоговая оценка строится на средних четырёх RMSRE,  в сантиметрах, граммах, см² и количестве плодов. MAE показывает среднюю абсолютную ошибку в этих же единицах

## Сравнение на development

Это объединённые прогнозы кросс-валидации. Лучшая эпоха CNN выбиралась по validation RMSRE

| Модель | Высота | Масса | Площадь листьев | Плоды | Среднее RMSRE ↓ |
|---|---:|---:|---:|---:|---:|
| Baseline, градиентный бустинг | 0,183 | 1,190 | 0,638 | 3,807 | 1,455 |
| Baseline + геометрия | 0,150 | 1,040 | 0,682 | 2,910 | 1,196 |
| ResNet18 RGB | 0,185 | 0,288 | 0,411 | 0,279 | 0,291 |
| ResNet18 RGB-D | 0,176 | 0,306 | 0,470 | 0,266 | 0,305 |
| Две ветви RGB и depth, 448 × 448 | 0,179 | 0,277 | 0,422 | 0,288 | 0,291 |

RGB лучше по средней CV-метрике. RGB-D выбрана для финальной оценки из-за приоритета высоты и числа плодов, по которым она дала небольшое улучшение RMSRE

## Доп. исследования

- Проверены маски по ExG, глубине и красному цвету (пришлось отказаться, т.к. цветовая маска может захватывать оранжевый поддон и посторонние объекты)
- Из глубины и внутренних параметров камеры получено облако точек; рассчитаны высота над опорой, площадь проекции
-  Геометрия улучшила baseline по высоте, но точное положение субстрата тяжело определить
- Проверены предположения о высоте горшка из статьи (10см и 7см)
- Проведена проверка leave-one-variety-out: обучение на трёх сортах, проверка на четвёртом, только внутри development
- Для RGB-модели средний RMSRE на оставленном сорте составил 0,548 для A, 0,439 для B, 0,720 для C и 0,327 для D
- Пробное центральное кадрирование RGB-D на одном фолде не улучшило ошибки плодов, тоже пришлось отказаться от включения в итоговую модель

## Ограничения

Снимок сверху содержит только видимые части растения. Плоды под листьями могут быть скрыты; отдельной разметки каждого плода нет, поэтому CNN оценивает общее число, а не обнаруживает и пересчитывает объекты

Площадь видимой проекции не равна всей площади всех листьев. Высота рассчитана относительно оценённой плоскости поддона; уровень субстрата принято было считать за высоту из доступных статей

Данных мало, разметка ручная, сорта представлены неравномерно. Случайное разбиение оценивает новые растения из того же набора условий, а проверка по сортам показала ограниченный перенос.

## Данные и установка

Источник: Righini et al. (2024), [4th Autonomous Greenhouse Challenge: Pre-trial Dwarf Tomato Measurements and Images](https://doi.org/10.4121/e1ee9de9-6ce9-4502-a37c-34b5b1372bed.v1), CC BY 4.0

Нужен архив индивидуальных растений с [официальной страницы](https://data.4tu.nl/datasets/e1ee9de9-6ce9-4502-a37c-34b5b1372bed). Размер архива - 7,45 Гб. 
(Изображения и веса моделей исключены из файлов проекта)

Для локального окружения используется Python 3.12; версии зависимостей зафиксированы в requirements.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-cnn.txt
python -m pip install --no-deps -e .
python -m unittest discover -s tests -q
python scripts/prepare_data.py --download
```

Скрипт подготовки проверяет архив и изображения и использует зафиксированные разбиения. Основные эксперименты запускаются отдельно, из корня проекта:

```bash
python scripts/run_baseline.py
python scripts/train_resnet18_rgb.py --epochs 20 --patience 5
python scripts/train_resnet18_rgbd.py --epochs 20 --patience 5
python scripts/run_geometry.py
python scripts/run_lovo.py
```

Обучение CNN желательно запускать на GPU в Kaggle или Colab. В текущем `run_lovo.py` CUDA ещё не выбирается автоматически - перед его переносом в Kaggle нужно исправить выбор устройства

 В `reports/` сохранены результаты исходных экспериментов.

`--smoke` запускает короткую техническую проверку без сохранения весов и не перезаписывает результаты полного обучения

КОнечная оценка реализована в `scripts/evaluate_holdout_rgbd.py`. Для неё нужны пять локальных весов `checkpoints/rgbd_resnet18/fold_0.pt` … `fold_4.pt` с хешами из протокола. Результат уже получен: повторная оценка блокируется счётчиком в `splits/metadata.json` и наличием итогового отчёта

## Структура

- `src/tomato_rgbd/` - метрика, данные, baseline и геометрические признаки
- `scripts/` - подготовка данных, обучение и оценка
- `tests/` - автоматические проверки
- `splits/` - фиксированные ID holdout и фолдов
- `reports/` - сохранённые прогнозы, метрики и иллюстрации
- `data/` и `checkpoints/` - локальные данные и веса, исключённые из Git


При реализации использовалась помощь AI; пояснения к модулям и проверки расчётов сохранены в проекте
